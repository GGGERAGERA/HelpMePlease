# Rocket Storm: профиль и точечное исправление, 31.10.2026

## Причина

В production MVP массовая выдача уже прогретых VFX из пулов вызывала работу `LiveVisualRuntime` над **всей сценой для каждого эффекта**:

- `PooledGameObject.Prepare → CaptureConfiguredHierarchy` обходил все `Targets`, даже когда требовались только компоненты одной ракеты/метки.
- `EnemyExplosion.Detonate → RegisterHierarchy` повторно регистрировал уже известный pooled-взрыв. `RegisterRoot` безусловно выставлял `refreshPending`, даже без новых компонентов. Следующий `Prepare → ApplyHierarchy` выполнял полный `Rebuild`.
- На 63 одновременных взрывах: 63 полных `Rebuild`, суммарно **2467,25 мс**, 3 214 969 `GC.Alloc` и **574 431 446 байт** аллокаций за кадр. Полный кадр — **2801,66 мс**. `GC.Collect` занял 61,66 мс; основная работа — сами повторные обходы, поиск правил и создание строк в `Rebuild`.
- Перед взрывами, при выдаче 63 падающих ракет, `CaptureConfiguredHierarchy` занял **290,80 мс** из **307,76 мс** кадра. При показе предупреждений — 297,44 из 321,23 мс.

Это CPU bottleneck с большим вторичным GC. На худшем кадре GPU — 2,45 мс; `Physics2D.OverlapCircleAll` — 0,69 мс, `ParticleSystem.Update` — 0,62 мс. Массовый Instantiate/Destroy и overdraw не объясняют измеренный многосекундный пик. Рендеринг эффектов не менялся.

## Исправление

Только `LiveVisualRuntime` меняет поведение:

1. Реестр компонентов теперь даёт прямой доступ к `VisualTarget`. Захват настроек проходит только по запрошенной иерархии с переиспользуемым списком компонентов.
2. Повторная регистрация известной иерархии не инвалидирует профиль сцены. Новые дочерние эффекты по-прежнему регистрируются и вызывают перестройку.

В пути ракеты/взрыва/пула добавлены метки Unity Profiler. Ракеты, предупреждения, взрывы, материалы, эмиссия, число атак, тайминги, урон, коллизии и release/cancel/dispose пулов сохранены. GDD не менялся: игровых правил и баланса это исправление не меняет.

## Один сценарий до и один после

Unity Editor **6000.3.13f1, DX11**, native Unity Profiler, Play Mode MVP, CPU без Deep Profile, GPU включён. Один и тот же development run: seed **5**, Gera, Stage 01, штатный prefab RocketStormEvent, viewport **1600×900**, VSync 0, target 60 FPS. Игрок неподвижен и неуязвим; обычные враги остановлены в измерительной оснастке для изоляции события. Production-данные не изменялись; настройки и пользовательские preferences восстановлены после выхода.

Записана первая штатная массовая волна: 2 с подготовки → предупреждения → 0,4 с падения → первые взрывы и 0,45 с после них. Остальной 30-секундный event не прогонялся. Параметры prefab: warning 2 с, interval 3,5 с, density 1; длительности и паттерн не переопределялись. Временные метки фаз взяты из реально наблюдавшихся предупреждений, падающих ракет и impacts.

| Фаза | Кадров до/после | Максимум кадра, мс до → после | Средний frame time, мс до → после | Средняя частота кадров до → после |
|---|---:|---:|---:|---:|
| Подготовка до предупреждений | 107 / 104 | 177,90 → 172,84 | 18,24 → 18,24 | 54,8 → 54,8 |
| Массовые предупреждения | 77 / 96 | 321,23 → 19,78 | 20,86 → 16,69 | 48,0 → 59,9 |

Частота — `1000 / средний frame time` соответствующей фазы; пики включены. Это короткий изолированный эпизод Editor с ограничением 60 FPS, а не замер полной игры/сборки. Число кадров различается из-за исходных остановок; число и геометрия атак совпадают.

В повторной записи:

- `CaptureConfiguredHierarchy` при выдаче 63 ракет: **290,80 → 0,54 мс**; сам `SpawnRocket`: **297,57 → 3,13 мс**.
- 63 детонации: **2747,83 → 5,54 мс**; полных `Rebuild` при предупреждениях/падении/взрывах больше нет.
- Пиковые аллокации фазы взрывов: **574 431 446 → 46 796 байт**.
- Манифесты до/после полностью совпали: **63 метки, 63 падающие ракеты, 63 взрыва**, каждый центр маркера совпадает с целью и последующим взрывом, диаметр маркера **4** соответствует радиусу поражения **2**. Несовпадений **0**, ошибок Unity в обоих сценариях **0**. Постоянные Radius=2 и damage=25 в production event не изменялись.
- Четыре узкие проверки pooled VFX прошли. Две новые проверки сначала воспроизвели лишний `Revision` и обращение к чужому target, затем прошли после исправления; существующие две проверки authored lifetime и порядка конфигурации/активации также прошли.

## Оставшееся ограничение

В подготовке остался отдельный пик **172,84 мс**: отложенный начальный `RefreshScene` с двумя `Rebuild` (149,91 мс, около 18,4 МБ аллокаций). Он был и до исправления (177,90 мс) и не связан с массовой выдачей ракет. Его исправление не входит в эту точечную работу. Полная нагрузка обычных врагов, другие паттерны волн и отдельная player-сборка не профилировались.

## Артефакты и повторение

`Artifacts/GeneratedQA/RocketStormProfile/` (локальные, gitignored):

- `before.data`, `after.data` — исходные записи Unity Profiler, открываются через Load в Profiler.
- `*-frames.csv`, `*-scopes.csv`, `*-peak-*.csv` — native main/GPU frames, GC Alloc, inclusive/self timings и call tree пиков.
- `*-observations.csv`, `*-manifest.txt`, `*-result.txt` — фазы, настройки, соответствие предупреждений/взрывов.
- `reuse-before.txt`, `reuse-after.txt` — красные/зелёные результаты узких регрессионных проверок.

Опциональный Editor harness: `RocketStormProfileVerification`, команды `before` / `after` / `reuse` через файл `Artifacts/GeneratedQA/RocketStormProfile/editor.request`; самопроизвольно ничего не запускает. Все новые измерительные runtime-типы ограничены `UNITY_EDITOR`. Длинные прогоны, общий suite, player builds и коммиты не выполнялись. После проверки Play Mode остановлен, production MVP открыта в Editor.

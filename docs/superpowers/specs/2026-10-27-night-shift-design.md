# Night Shift: Creative Director для Subject#42

Основание: прямой запрос пользователя от 27.10.2026 на автономную локальную работу до семи часов. Цель — качество существующего production-забега для публичной демоверсии и показа издателю. Пользователь делегировал выбор задач и экспериментов; дополнительные циклы согласования не нужны.

## Решение

Один Node.js-процесс вызывает официальный `codex exec` последовательно: исследование и выбор → ограниченная работа → проверка Unity → новая оценка. Следующий выбор получает фактический результат предыдущего цикла, а не заранее составленную очередь. Node.js уже установлен; зависимостей npm не требуется. SDK добавил бы ненужную установку; автоматизация чата не даёт нужного контроля процессов.

Planner работает read-only, исполнитель — workspace-write. Оба запускаются с `--ignore-user-config`, `approval_policy=never`, Windows unelevated sandbox. Sandbox не отключается; внешние MCP и субагенты не подключаются. Сохранённая CLI-авторизация используется без чтения/копирования секретов. Unity запускается хостом с фиксированным набором тестов, без исполнения произвольных команд из ответа модели.

## Ограничения

- Никаких git add, commit, checkout/switch, push, merge, публикации, установки пакетов и изменения пользовательских сохранений.
- Никаких переключений веток/новых worktrees: текущий пользовательский checkout, чистый на старте.
- Артефакты, JSONL и XML — в игнорируемом `Artifacts/GeneratedQA/NightShift/<session>`; постоянные отчёты — `NIGHT_REPORT.md`, `PLAYTEST_CHECKLIST.md`.
- Один процесс/один Unity Editor; занятый Editor означает остановку без принудительного закрытия.
- Лимит 7 часов, ограничение каждого процесса, STOP-файл, блокировка второго запуска, остановка при ошибке инфраструктуры, изменении HEAD/index или контрольных файлов оркестратора.
- Снимок Unity PlayerPrefs в реестре перед тестами, восстановление в finally; незавершённый снимок требует восстановления до новых тестов. Не запускать игру параллельно.
- Production: подтверждённые исправления существующего поведения. Experimental: гипотеза с семью ответами из запроса, выключенная по умолчанию, отдельное включение и откат. Не считать компиляцию принятием дизайна.
- Никаких обещаний субъективного улучшения по боту. Неизмеренные event gaps/FPS не выдумывать.

## GDD и исследование

До изменения дизайна прочитать Core, нужный раздел Bible и сверку 26.10; записать раздел, до/после, решение игрока, основание, проверку и отказ. Принятое правило синхронизировать с GDD в той же работе. Основные ориентиры: Bible §4 (ядро), §5.2 (события), §7 (риск/награда), §10 (фильтр идей), §12–13 (метрики/границы свидетельств).

Первая работа должна установить связность production: StartScreen → MainMenu → MVP (три локации) → босс → MainMenu → второй выход. Использовать существующие Golden Path / BotBatchRunner / Combat Lab / FEEL LAB, не создавать параллельную систему.

## Приёмка

1. Unit-проверки реального контроллера: следующий выбор зависит от предыдущего теста; пустой XML/падение/таймаут не успех; STOP/дедлайн/блокировка завершают работу.
2. Два настоящих последовательных успешных цикла CLI с сохранёнными решениями, работой и Unity XML. Минимум один свежий Golden Path с боссом и вторым выходом. При воспроизводимом FAIL разрешены дополнительные динамические repair-циклы (до 8/сессию), исходные FAIL сохраняются; допуск требует двух новых последовательных PASS. История переносится между сессиями для продолжения диагностики.
3. Готовность объявляется только после успешного smoke. При проблеме сохранить факты и не запускать семичасовую работу.

Предыдущее задание Night Shift в репозитории не найдено. Доступная история чата «Ночная автономная работа» подтверждает локальную работу без участия пользователя и динамический выбор, но не содержит полного старого текста требований. Консервативные ограничения выше сохранены явно; неизвестные требования не объявляются восстановленными.

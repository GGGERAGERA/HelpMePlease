# Перенос лабораторных врагов в production MVP

**Цель:** подключить утверждённые пользователем готовые варианты, без нового AI и перебалансировки.
**GDD:** [Bible §4.4](../../../Assets/_Project/Documentation/Subject42_Game_Design_Bible.md#44-контроль-толпы); Core §4. Прочитаны Core и сверка 26.10.2026.
**Основание:** прямой запрос пользователя 02.11.2026 после лабораторной оценки.
**До → после:** ограниченная дуга/короткий общий таран → непрерывная спираль 7 м/с и независимый таран 24 м/с × 1,2 с; HP 16/32, редкий одноразовый направленный щит. Игрок переводит фронт огня и уклоняется от фиксированных линий. Четыре паука становятся визуальными вариантами массового преследователя без новых способностей.

## Границы

Работа в текущем checkout по прямому запросу пользователя; без worktree, веток, git add, коммитов и push. Существующие несвязанные изменения сохраняются. Профили 4–10 неактивны и не перебалансируются. p_Boss2 остаётся боссом, MiniTurret4 и оружие/модули/орбиты не меняются; Перехват остаётся лабораторным. Баланс оценивает пользователь.

**Критерий:** production использует готовые варианты с утверждёнными параметрами, все пять массовых видов доступны обычному спаунеру, суммарный вес/общий лимит/темп класса сохранены. Проверка отделяет статические данные, короткий Editor-сценарий и ручной плейтест отдельной сборки (последний не выполняется).

## Выполнение и границы доказательств, 02.11.2026

- `EnemyChaseMovement` использует прежний лабораторный код с production-флагом prefab; настройки доступны вне Editor/Development. Общие `ramOwner`, `ramNextAllowedAt` и admission удалены. Неиспользуемые `_Start` prefab сохранены без изменений.
- `EnemyTacticalTimedShield` — вынесенный существующий таймер/сборка щита; production-prefab содержит заранее собранную выключенную защиту. На старте выбираются вероятность и задержка, при активации запускается только EnemyDirectionalShield. Лабораторный адаптер сохраняет seeded chance и собственную паузу, не применяет визуальное масштабирование второй раз.
- Четыре production spider-prefab побайтово совпадают с LabSpiderWhite/Dark/BigGait/Blue. Они сохраняют общий identity `Tupik`, исходные HP, контакт, loot, события и controllers. **Белый Spider1 статичен в авторском источнике**; анимации ходьбы есть у остальных трёх, новая анимация белому не создавалась.
- Сверка с исходным снимком: все **18 фаз** трёх активных профилей сохраняют общий вес/лимит рядового класса, timing, maxAlive и прочие записи. Из tactical-записей удалены только cap 2/1 и exact-флаг; веса и секторы сохранены. SHA-256 несвязанных исходно изменённых/неотслеживаемых файлов совпадают, включая лабораторную сцену, оружие/орбиты и MiniTurret4.
- Короткий `EnemyProductionTransferSmoke.BunkerSpawnerMovementShieldsSpidersAndWeapons`: **1/1 Passed**. Настоящий вход BunkerRunStarter → MVP, затем сокращённый переход API к сектору 3. Вызовы цикла ускорены только внутри проверки, без изменения данных.

HP после старта таймера совпадает с назначенным спаунером. Прежний секторный множитель HP ×1,08 в третьем секторе сохранён; щит не добавляет HP.

# Subject#42 — AI Studio V1

Эксперимент организации разработки, 02.11.2026. Использует штатных подагентов Codex; собственного оркестратора, сервиса или Unity runtime нет.

Локально проверено: `codex-cli 0.166.0-alpha.5.1` обнаруживает все пять TOML-ролей; новый штатный `debug prompt-input` перечисляет их в `spawn_agent.agent_type`. В текущем чате схема инструмента выбора роли не предоставляла, поэтому демонстрационные подагенты явно прочитали свои TOML. Это подтверждает discovery и применение инструкций специалистами; автоматический spawn по имени роли в текущем чате не проверен. Формат: [официальная документация](https://learn.chatgpt.com/docs/agent-configuration/subagents).

Общая база: [действующие решения](CURRENT_DECISIONS.md). Отдельно: [исторические этапы и гипотезы](HISTORY_AND_HYPOTHESES.md). Ни один из этих указателей не заменяет исходный GDD.

## Запуск и границы

Вызов: «Астра, AI Studio: [задача]. Привлеки [нужные роли] для независимого анализа». Не запускать всю студию на каждую правку. Для короткой понятной задачи достаточно Астры.

Роли обнаруживаются Codex по `.codex/agents/*.toml` из корня репозитория. В клиенте с выбором custom agent использовать `name` из TOML. Если текущий `spawn_agent` не принимает `agent_type`, Астра создаёт штатного подагента с чистым контекстом и явно поручает прочитать соответствующий TOML и эти два документа. Это явная передача инструкции, а не доказательство автоматического применения TOML. Не создавать отдельные пользовательские чаты вместо подагентов и не обходить ограничения клиента.

Файлы не фиксируют модель или effort: наследовать настройки родителя; при явном выборе пользователя применять его настройки. Не менять глобальный config, лимиты, плагины или разрешения ради V1. Текущий чат допускает четыре активных агента вместе с координатором: максимум три специалиста одновременно; остальные запускаются следующей волной. Лимит зависит от клиента, проверять доступные инструменты.

`Do not edit` в инструкции — правило поведения, не отдельная песочница. Подагенты наследуют permissions/MCP родителя. Не обещать техническую изоляцию записи, которой клиент не предоставляет. Астра проверяет diff до и после.

## Ответственность

| Роль / name | Когда нужна | Конкретный результат |
| --- | --- | --- |
| Game Designer / `game_designer` | Механики, прогрессия, решения игрока | Существующее → предлагаемое, GDD, новое решение, цена риска, kill criteria |
| Unity Architect / `unity_architect` | Unity 2D/C#, ownership, lifecycle, стоимость интеграции | Владелец поведения, реальные зависимости, минимальная точка расширения, риски CPU/GC/сцен/сохранений |
| Art Director / `art_director` | Pixel-art, целостность, читаемость | Реальные ассеты и импорт/масштаб, соответствие стилю, конкретный конфликт читаемости, план Game View проверки |
| Level Designer / `level_designer` | Пространство, маршрут, события, орбитальная конструкция | Геометрия выбора, вход/выход/отказ, достижимость текущим билдом, опасные сочетания |
| QA Critic / `qa_critic` | Независимая проверка требований и рисков | Проверяемые замечания с серьёзностью и источниками, пробелы доказательств, минимальная адресная проверка |

Главная Астра — координатор и единственный интегратор правок Unity: кода, сцен, prefab, assets и настроек. Специалисты V1 только читают и возвращают выводы. Даже просьба координатора «реализуй» не меняет этот контракт без явного пересмотра пользователем. Общие файлы одновременно не редактируются. Специалисты не запускают Unity, Play Mode, тесты, сборки, git add/commit/checkout и других подагентов.

## Один рабочий проход

1. Астра читает AGENTS.md, Core, затронутые разделы Bible, PROJECT_MAP и DEV_FAST_WORKFLOW; сверяет рабочий diff. [CURRENT_DECISIONS.md](CURRENT_DECISIONS.md) — навигационный срез, не второй GDD.
2. Формирует короткий общий brief: вопрос, текущие факты, гипотеза, границы, источники, ожидаемый результат и лимит ответа. Независимым ролям передаёт одинаковый brief без ответов соседей; чистый контекст вместо истории всего чата.
3. Запускает только нужные роли. Параллельно — независимый анализ; зависимое обсуждение — после первых результатов. Не редактирует рассматриваемые общие файлы до окончания чтения специалистами.
4. Каждый сначала возвращает конкретные выводы: факт и источник; предложение и его статус; риск/контрпример; дешёвая проверка. Отсутствие доказательств называет явно. Ответ обычно до 500 слов. Не заменяет выводы большим планом или перечитыванием всего проекта.
5. Астра проверяет источники спорных выводов, убирает дубли и сводит разногласия. Не принимает решение голосованием. QA критикует требования независимо и затем адресно проверяет итог, если в нём появились новые условия.
6. Непринятая идея остаётся гипотезой. Геймдизайн становится требованием только после явного утверждения пользователя. Интересность, комфорт и субъективное качество оценивает пользователь. При принятом изменении — конкретный раздел GDD, до → после, основание, проверка; обновление Bible/Core по AGENTS.md.
7. Внедряет только Астра, в пределах разрешённого запроса. Затем только необходимая адресная проверка по DEV_FAST_WORKFLOW: изменение → запуск → реальный результат → коррекция при необходимости. Уже зелёную проверку без новой причины не повторять.

Для проверки Unity заранее указать абсолютный проект, production-сцену, версию/PID Editor и commit/хеши проверяемых файлов. QA-копия не подтверждает пользовательский Editor. Для визуала — полная инициализация production-сцены/игрока, штатная игровая камера, настоящий PNG Game View, открытие и визуальный осмотр; анимация — минимум два разнесённых кадра. Отдельно различать наличие, активность и видимость. Непроверенный физический ввод и восприятие не объявлять подтверждёнными.

## Затраты и остановка

Сравнивать одну задачу, одинаковый brief/лимит/уровень проверки. Разделять разовую настройку студии, первичный анализ, последующую критику и интеграцию. Фиксировать wall time от dispatch до результата и сумму длительностей ветвей; сумма — приблизительное занятое время агентов, не CPU, токены или деньги. Не выводить стоимость из длины ответа. Если точных tokens/cost нет, так и писать. Контрольный одиночный проход не читать до фиксации основного решения; отмечать различия контекста/очерёдности.

Остановить анализ, когда на вопрос дан проверяемый ответ и критические разногласия объяснены. Не запускать массовые тесты ради отчёта. Диагностика и разовые scripts/reports — только отдельная подпапка существующего gitignored `Artifacts/GeneratedQA`; чужие Artifacts не трогать. Коммиты, staging и переключение веток запрещены без прямого запроса.

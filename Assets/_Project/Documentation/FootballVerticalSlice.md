# Football — исходный дизайн с authored-границами

Источник композиции: `MainMenu.unity` из commit `7fc47f78`, до Football Vertical Slice pass. Сравнение предыдущего pass выполнено до правок и описано в `FootballCorrectionDiff.md`.

Итоговый контейнер: `Assets/_Project/prefabs/MinigameArena_VS.prefab`; его GUID сохранён, экземпляр подключён в `MainMenu`.

Возвращено из исходной сцены:

- Поле 24×28, прежние зоны 20/40/40, их координаты, размеры, текстуры и цвета; исходные StartZone, BallSpawns, anomaly/target lanes.
- Четыре мяча, две движущиеся gravity-анomalии и три движущиеся цветные цели. Их исходные параметры и динамическая механика сохранены.
- Два исходных корня ворот со всем mesh/net-контентом, материалами, масштабами и локальными координатами. Попадание снова даёт +20 очков и не завершает игру.
- Раунд на 60 секунд, счёт, рекорд, цели +2/+5/+10, повторное появление целей.
- Исходная граница игрока над нижней зоной. Игрок играет из shooting area; мячи проходят через эту границу. Исключения столкновений задаются только зарегистрированным мячам, без глобального поиска Collider2D.
- Прежний правый HUD времени, счёта, рекорда, легенды и управления. Под ним только небольшая кнопка «Сброс мячей [R]».

Удалено из привнесённого redesign: поле 24×16, две новые bank-преграды, новые прямоугольные ворота, дополнительные одноцветные зоны и ореол, телепорт игрока на START, правило победы по первому голу, большая нижняя плашка HUD.

Намеренно не возвращены: FootballArenaLayout, автоматическое перестроение зон/anchors/ворот в Awake/OnValidate/Update, runtime-builders стен/ворот/player boundary, глобальный поиск collision exceptions, legacy-поля и runtime debug mesh. Три экземпляра целей подготовлены в prefab; лишние runtime-пулы геометрии не восстанавливаются. Движение аномалий/целей, случайный вид цели и respawn — исходная gameplay-динамика, а не генерация основной геометрии.

Сохранённая техническая часть:

- Внешние Collider2D по исходному ArenaBounds: левая, правая, верхняя стены, нижние боковые участки и края входа. Проход постоянно открыт; выход игрока из зоны сбрасывает раунд. Новый контур не переставляет исходный контент.
- PhysicsMaterial2D FootballVS_Bounce: friction 0, bounce 0.98. Мячи: gravity 0, linear damping 0, angular damping 0.05, Continuous CCD, Interpolate, FreezeRotation, max speed 22. Исходные параметры заряда/силы удара/ведения восстановлены из старых instances. Существующий BallRollVisual ограничивает скорость в FixedUpdate и обрабатывает ведение там же.
- R / компактная кнопка — сброс активных мячей в исходные свободные spawn points; отдельный потерянный или застрявший мяч восстанавливается без сброса остальных. Stuck recovery — 5 секунд, с исключением непосредственного взаимодействия игрока с мячом.
- Authored CameraBounds 26×30 вокруг прежнего поля. Существующий CameraFollow кадрирует эту область; поля закрывают пространство за ней, не перекрывая прежний HUD. Камера восстанавливается после окончания/отмены/отключения раунда.
- Gizmos показывают исходные зоны, lanes и физический контур. Производственная геометрия не содержит debug-разметки.

Что меняет gameplay относительно оригинала: реальные внешние стены отражают мячи, проход остаётся открытым; более упругие отскоки и max speed меняют физическое ощущение; ручной reset и recovery облегчают восстановление игры. Число объектов, правила очков/таймера, позиции зон, ограничение игрока и исходная динамика возвращены, а не заменены новым дизайном.

Проверка: Unity 6000.3.13f1; реальная MainMenu в Play Mode. `FootballSmoke.txt` содержит результаты проверок исходного gameplay, движения целей/аномалий, очков, таймера, restart, физических стен/углов/CCD, recovery, границы игрока, camera bounds и lifecycle. `FootballGeometryAudit.txt` сравнивает локальные позиции, повороты и масштабы исходных зон, спавнов, lanes, ворот, StartZone и player boundary с восстановленным prefab. Кадр — `FootballArena_HUD.png`.

Повторить smoke: сохранить MainMenu, Tools → Subject42 → Football → Play Mode Smoke Test. Тест управляет реальными Rigidbody2D программно и временно выключает CharacterMovement2D для проверки collision-сценариев; это не ручной UX playtest и не standalone build. Исходная сохранённая композиция ворот намеренно не переполирована и не перестроена.

Исправление ввода: блокировка удара учитывает только GraphicRaycaster. Physics2DRaycaster арены больше не блокирует ЛКМ. Заслонка EntranceGate и её serialized/runtime-зависимости удалены.

Регрессия открытого прохода: 30/30 Play Mode-проверок, включая физический выход игрока, сброс и повторный запуск. Реальный ЛКМ через Game View запустил неподвижный мяч: скорость (4.06, 2.76); отдельная длительность полного заряда в этом прогоне не измерялась.


## Старт по входу и статистика ворот (следующая итерация)

Источник текущих ворот — два экземпляра FootBallGates1 Variant, расставленные пользователем в MainMenu. Их позиции и модели сохранены; ссылки на старые ворота заменены. У текущих стоек исходные 2D-коллайдеры были вырождены поворотами вложенных 3D-трансформов. В контейнере ворот подготовлены статические стойки/задняя граница и триггер гола в плоскости XY, с материалом отскока.

Старт теперь происходит по входу физического коллайдера игрока в authored BoxCollider2D 3×3. Клик, BunkerStation, hover-outline и terminal у этой зоны удалены. Зелёные угловые метки и прозрачная напольная заливка заменяют красный квадрат. SortingGroup стартовой зоны больше не отделяется от сортировки арены (sortAtRoot=false); маркер располагается над полем и под игроком. Во время раунда метка скрыта. Окончание раунда при стоянии в триггере не запускает следующий: нужен выход и повторный вход.

FootballMinigame хранит GoalCount и GoalScore текущего раунда; каждое попадание в ворота добавляет +20 к общему счёту и обновляет строку «ГОЛЫ N / +X ОЧКОВ». В воротах появляются короткая зелёная вспышка и «ГОЛ +20». Повторные контакты не дают дополнительные очки до выхода мяча. Reset/новый раунд обнуляет статистику и эффекты; завершение сохраняет итог на HUD.

Проверки дополнены реальными бросками в оба видимых створа, статистикой/эффектом/HUD, сбросом и повторным входом. Кадры: FootballGoals_HUD.png, FootballStart_Idle.png. Это Play Mode и визуальная проверка, без standalone build.

Финальный прогон: 40 PASS, 0 FAIL. Удалён больше не используемый BunkerMinigameTerminal (ссылок в assets и production C# не осталось).

За попадание в цветную цель появляются +2/+5/+10: цвет соответствует цели, число поднимается на 1.1 world units и плавно исчезает за 1.25 секунды. Для каждой цели подготовлены три независимые текстовые метки в prefab (при текущем respawn 0.45s этого хватает на перекрывающиеся эффекты). Они не перемещаются вместе с целью при respawn и очищаются при окончании/сбросе раунда. Runtime не создаёт объекты или материалы для этих надписей.

Проверка всплывающих очков: 44 PASS / 0 FAIL, включая число начисленных очков, движение вверх, затухание, сохранение позиции при respawn и очистку при reset. Кадр: FootballTargetPoints.png.


Поля притяжения/отталкивания: размер 7×3.2 вместо 4.5×3.2; крайние точки существующих горизонтальных lanes ограничены шириной поля, чтобы визуал и коллайдер оставались внутри игровой зоны. Первая зона начинает с притяжения (фиолетовая), вторая — с отталкивания (голубая). Через случайные 10–15 игровых секунд роли меняются; последние 2 секунды интервала — плавный переход силы через ноль и цвета. Зоны в каждый момент имеют противоположную полярность. Сброс/новый раунд возвращает начальные роли.

В GravityZone добавлена опциональная радиальная полярность; обычные зоны сохраняют прежнее притяжение. Цвет/поток задаются через MaterialPropertyBlock, без изменения общего материала. Фаза визуального потока накапливается отдельно: смена направления не перескакивает по глобальному времени. Мяч проверен физически на притяжение/отталкивание до и после обмена ролями.

Финальная проверка полярности: 53 PASS / 0 FAIL; общий материал не изменялся. Кадр: FootballPolarity.png.

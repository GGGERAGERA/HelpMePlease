# Production sector props — author-controlled scatter

Edit `Resources/PropScatterProfile.asset` in the Inspector. Add/remove elements in
`entries` and drag an existing visual prefab into `prefab`. Each entry has `weight`,
`minCount`, `maxCount`, optional `varyScale / scaleRange` and
`varyRotation / rotationRange` (degrees). No art is generated by scattering.

`totalCount` is the sector budget. Minima are placed first in array order, then
remaining slots are selected by weight without exceeding maxima. Weight zero
disables extras; set both counts to zero or remove the entry to disable it entirely.
Safety wins over counts when space is exhausted or minima exceed the budget.

F1 → VISUAL → PROP SCATTER: Regenerate Props, Clear Props, Seed +1, Seed -1.
The current seed and count are shown. Seed buttons immediately regenerate only
decoration. They do not save back to the profile or regenerate gameplay objects.
Edit the profile's `seed` to change the persistent base seed.

The seed combines the profile seed and the sector exit location. Identical seed,
profile and protected world geometry reproduce the layout, even after the player
moves. The original player spawn is retained. Removed/added gameplay objects can
change available positions on later regenerations. Unity gameplay RNG is untouched.

The scatter uses spaced candidate sampling, biased toward empty areas; no grid,
clusters, noise map, biome or terrain generation. The default is 238 objects on
the 100 x 100 playable area, at least 3.5 units apart. Prefab size also contributes
to clearance from walls, edges, initial player spawn, exit, anomaly/event centers,
interactables, containers and resource nodes. Narrow gaps near walls remain clear.

Decoration is created after gameplay objects. All accepted prefabs must be visual
only: prefabs containing scripts, Collider2D or Rigidbody2D are skipped with a warning.
Sprites use Background / -105, below actors, ORBITAL and interactables.

Smoke: `PropScatterSmoke.ProductionProfileTwoSeeds` — one production Play Mode
session, two seed screenshots, deterministic regeneration, counts/spacing,
clear/seed commands and unchanged gameplay RNG/colliders.

## Existing art

Nine visual-only prefab variants reuse the existing `BunkerCase1`, `BunkerElements1`
and `BunkerElements3` textures through serialized Sprite assets. No texture copies,
colliders, behaviours, loot, lights or minimap markers are added to the prefabs.

Prefabs: `Resources/SectorProps`. Sprite assets and placement helper live here.
Regenerate assets with **Tools > Subject42 > Environment > Author sector props**.
Source crop rectangles, scale and palette are in `Editor/ProductionPropsAuthoring.cs`.

`ProductionExplorationSectorController.Initialize` owns the `ProductionSectorProps`
instance. It loads the profile from Resources unless a scene override is assigned.
This connects props to every production MVP sector, including the final sector.
They are destroyed with the sector.

- About 10–20 props per typical view, depending on ORBITAL framing, zoom and position.
- Local System.Random; no gameplay RNG consumption.
- Profile scale/rotation variation and horizontal flips.
- ColdAshLit material, muted tint, Background / -105 (floor -110, micro marks -109).
  Player, enemies, XP, ORBITAL, events and interactables render above this entire pass.

Reuse the existing `ColdAshProductionTests.ProductionMovementCrowdsEventsSectorsAndBoss`
smoke test for production screenshots, movement through props, moving crowds, ORBITAL
hits, breakables, events, sector transitions and the final boss. This is a controlled
QA run with player invulnerability and injected crowds, not a balance/playthrough test.
